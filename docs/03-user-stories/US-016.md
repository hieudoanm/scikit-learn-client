# US-016: Fit a Q-function from an experience log

## User Story

**As a** practitioner,
**I want to** upload a log of state transitions with actions and rewards and export a fitted Q-function,
**so that** I can run a greedy policy in another runtime without an RL framework.

## Acceptance Criteria

- Given an experience CSV (state features, action, reward, next-state, done, episode), when I choose Reinforcement learning, map the state columns, and declare the experience columns, then job create succeeds without a label.
- Given a label column, when I submit a reinforcement-learning job, then `400 INVALID_COLUMN_MAP`.
- Given neither `nextStateColumns` nor `episodeColumn`, when I submit, then `400 INVALID_COLUMN_MAP`.
- Given `gamma` outside 0…1 or `n_iterations` outside 1…50, then `400 INVALID_HYPERPARAMETERS`.
- Given a completed job, then `meanReward`, `meanQ`, `tdErrorMean`, `tdErrorStd`, and `actions` are returned (plus `episodeCount` and `meanEpisodeReturn` when an episode column was mapped).
- Given the ONNX artefact, then Q-values match sklearn for the same state and one-hot action inputs.
