# skl — Result Charts

_Part of [07-ui-ux-design.md](../../07-ui-ux-design.md)._

> **Status: implemented.** Charts are generated by the backend worker, stored in `job_metrics.charts`, returned in the job poll payload, and rendered on the job status screen via visx components. Reinforcement-learning charts are specified for Phase 11.

## 1. Purpose and principles

Charts exist to answer a specific question about the trained model. They **augment** the
task-specific metrics list, they never replace it: every number behind a chart stays readable as
text in the metrics section.

1. **One question per chart.** The question is the chart title/caption ("Which classes are
   confused?", "Is the error constant across the range?").
2. **Bounded payload.** Every series is capped and sampled/binned on the server so the job poll
   payload stays small (see [§4](#4-data-contract-implemented)).
3. **Honest.** Label axes and units, state the evaluation scope (hold-out vs in-sample), and never
   imply more precision than the data supports.
4. **Accessible.** Colour is never the only channel and each chart exposes its values as text
   (see [§6](#6-accessibility)).
5. **Deterministic.** Any sampling or binning uses the job `randomSeed`.
6. **Degenerate inputs hide the chart**, with a short note, rather than render an empty frame
   (see [§7](#7-empty-and-degenerate-states)).

Charts are a **local, single-user** feature: they visualise the model's own evaluation output on
the user's machine. No chart data leaves the instance, and `docs/12-operations/security.md` still
governs what may be logged.

## 2. Where charts appear

- **Job status** `/jobs/[jobId]` in the `completed` state only: a **Model report** section placed
  between **Metrics** and **Downloads**.
- Responsive grid: one column on mobile, two columns from `sm` and up. Each chart is a `card`
  (`card bg-base-100 shadow`, per [`components.md`](./components.md)) with a heading, a one-line
  caption, and the plot.
- Not rendered while `queued` … `exporting`, nor on `failed` (the error alert is the whole report).
- Component: `packages/frontend/src/components/charts/ModelReport.tsx`

## 3. Charts by task

Priorities follow [`02-features.md`](../../02-features.md): **P0** is the default report for the
task, **P1** is an enhancement, **P2** ships only if a concrete need appears. **All P0 and P1 charts are implemented.**

Chart ids (`C1`, `R1`, …) are stable references for tests and for the frontend component mapping.

### 3.1 Classification and semi-supervised

| Id  | Chart                               | Question                                       | Type           | Priority |
| --- | ----------------------------------- | ---------------------------------------------- | -------------- | -------- |
| C1  | Confusion matrix                    | Which classes does the model confuse?          | Heatmap        | P0       |
| C2  | Per-class precision / recall / F1   | Which classes are strong or weak?              | Grouped bars   | P0       |
| C3  | Metric summary (accuracy, P, R, F1) | How good is the model overall?                 | Bars, 0–1 axis | P1       |
| C4  | ROC / precision–recall curve        | What is the threshold trade-off? (binary only) | Line           | P2       |

C2 is derivable from C1 (row/column sums) and is the more legible of the two for many classes;
show C2 alone when the class count exceeds the C1 display cap.

### 3.2 Semi-supervised only

| Id  | Chart                  | Question                                  | Type                 | Priority |
| --- | ---------------------- | ----------------------------------------- | -------------------- | -------- |
| S1  | Label coverage         | How much of the label column was filled?  | Stacked bar / donut  | P0       |
| S2  | Self-training progress | Did self-training converge, and how fast? | Cumulative step/line | P1       |

S1 uses the existing `labelledRows` / `unlabelledRows` metrics. S2 plots cumulative labelled rows
per iteration from `SelfTrainingClassifier.labeled_iter_` (0 = originally labelled, _k_ = labelled
in iteration _k_, −1 = never labelled) and marks the stopping iteration (`n_iter_`).

### 3.3 Regression

| Id  | Chart                  | Question                                               | Type                   | Priority |
| --- | ---------------------- | ------------------------------------------------------ | ---------------------- | -------- |
| R1  | Predicted vs actual    | How close are predictions, over the whole range?       | Scatter + `y = x` line | P0       |
| R2  | Residuals vs predicted | Is the error constant, or does it grow with the value? | Scatter + zero line    | P0       |
| R3  | Residual distribution  | Are the errors centred and roughly normal?             | Histogram              | P1       |

R1 is the default regression chart. R2 shows systematic bias or heteroscedasticity that a single
RMSE cannot.

### 3.4 Clustering

| Id  | Chart                   | Question                                        | Type                                            | Priority |
| --- | ----------------------- | ----------------------------------------------- | ----------------------------------------------- | -------- |
| K1  | Cluster scatter (PCA-2) | Are the clusters separated in feature space?    | Scatter, coloured by cluster                    | P0       |
| K2  | Cluster sizes           | Are the clusters balanced?                      | Bars                                            | P0       |
| K3  | Silhouette plot         | Which clusters are cohesive, and which overlap? | Horizontal bars, per sample, grouped by cluster | P1       |

K1 uses a 2-component PCA of the preprocessed matrix purely as a 2-D projection for display; the
axis captions say so. When `silhouette` is omitted by the worker (all rows identical), hide K3 and
show the "separation is undefined" note.

### 3.5 Anomaly detection

| Id  | Chart                   | Question                                                           | Type                           | Priority |
| --- | ----------------------- | ------------------------------------------------------------------ | ------------------------------ | -------- |
| A1  | Score distribution      | Where is the decision boundary, and how separated are the classes? | Histogram + threshold line     | P0       |
| A2  | Anomaly vs normal split | What share of rows is flagged?                                     | Donut / stacked bar            | P0       |
| A3  | Score by row order      | Are anomalies spread out, or in bursts?                            | Scatter, flagged points marked | P1       |

Scores are `decision_function` values; the threshold is the score at which a row becomes an
anomaly (distinct from the `contamination` hyperparameter, which is displayed in the job summary).

### 3.6 Cross-model (classification, regression, semi-supervised)

| Id  | Chart                             | Question                           | Type       | Priority |
| --- | --------------------------------- | ---------------------------------- | ---------- | -------- |
| M1  | Feature importance / coefficients | Which inputs drive the prediction? | Top-N bars | P1       |

M1 reads `coef_` (linear models) or `feature_importances_` (tree ensembles), aggregates the
expanded preprocessor output back to the **original feature columns** (summing one-hot/encoded
contributions per source column), and shows the top N (default 10).

**MLPs (`mlp_classifier`, `mlp_regressor`)** expose neither attribute — the weights live in
`coefs_` (a list of per-layer matrices) with `intercepts_`. M1 therefore aggregates the
**first hidden layer** (`coefs_[0]`, shape `n_inputs × n_hidden`): the per-input importance is the
mean absolute outgoing weight across that layer's units, which ranks inputs the same way `coef_`
does for a linear model. `method` reports `mlp_weights`.

For any other estimator with neither attribute, permutation importance is computed as a fallback
(`method: 'permutation_importance'`) using a bounded sample. Clustering and anomaly-detection
models omit M1.

### 3.7 Reinforcement learning (Phase 11)

| Id  | Chart                 | Question                                                      | Type            | Priority |
| --- | --------------------- | ------------------------------------------------------------- | --------------- | -------- |
| RL1 | Q-value distribution  | How are fitted Q-values spread across evaluation transitions? | Histogram       | P0       |
| RL2 | TD error distribution | Are Bellman residuals centred and small?                      | Histogram       | P0       |
| RL3 | Mean Q per iteration  | Did FQI converge over sweeps?                                 | Line            | P0       |
| RL4 | Episode returns       | What returns did episodes achieve in the log?                 | Histogram / bar | P1       |

RL1–RL3 use `metrics.tdErrorMean`, `metrics.tdErrorStd`, and per-iteration Q/TD summaries collected during FQI sweeps (stored in `charts`). RL4 uses `metrics.episodeCount` and `metrics.meanEpisodeReturn` when an episode column was declared; otherwise RL4 is hidden. Reinforcement-learning jobs do not show M1 (feature importance) by default.

### 3.8 Neural nets (MLP, classification and regression)

| Id   | Chart         | Question                            | Type | Priority |
| ---- | ------------- | ----------------------------------- | ---- | -------- |
| MLP1 | Training loss | Did the MLP converge, and how fast? | Line | P1       |

MLP1 plots the solver's per-epoch objective from `MLPClassifier.loss_curve_` /
`MLPRegressor.loss_curve_` as one point per epoch (`epoch` is 1-based; `loss[i]` is the objective
after epoch `i`). It is the MLP counterpart of S2 (self-training progress) and RL3 (FQI
convergence): the spec already gives every iterative task family a convergence chart.

MLP1 is **conditional on the solver**: `loss_curve_` is populated for `adam` and `sgd`, and is
`None` for `lbfgs`. When it is absent, the card is hidden — the same conditional pattern as RL4
(no episode column) and K3 (undefined silhouette). The series has at most `max_iter` points
(fewer with `early_stopping`). MLP jobs otherwise show their task family's charts unchanged
(C1/C2/M1 for classification, R1/R2/R3/M1 for regression).

## 4. Data contract (implemented)

The worker generates chart data in `packages/backend/src/training/charts/` (one module per task family, dispatched from `packages/backend/src/training/core/pipeline.py`) with feature importance collected by `_collect_feature_importance`, stores it in `job_metrics.charts` (migration `0002_add_charts_column.py`), and returns it in the poll payload. All values are JSON-serialisable and capped so the terminal poll payload stays in the low tens of KB. Reinforcement-learning charts follow §3.7; MLP jobs add `mlpProgress` (§3.8) on top of their task family's charts.

### 4.1 Data contract table

| `charts` key        | Task(s)                          | Shape                                                              | Cap                    |
| ------------------- | -------------------------------- | ------------------------------------------------------------------ | ---------------------- |
| `classes`           | classification, semi             | string[]                                                           | first 50, else note    |
| `confusionMatrix`   | classification, semi             | number[][] (`len(classes) × len(classes)`)                         | 50 × 50                |
| `perClass`          | classification, semi             | `{ class, precision, recall, f1, support }[]`                      | 50                     |
| `selfTraining`      | semi                             | `{ iterations, newlyLabelled: number[] }`                          | `max_iter` entries     |
| `labelCoverage`     | semi                             | `{ labelled: number, unlabelled: number }`                         | —                      |
| `regressionPoints`  | regression                       | `{ predicted: number[], actual: number[] }`                        | 500 points (seeded)    |
| `residuals`         | regression                       | `{ predicted: number[], residuals: number[] }`                     | 500 points (seeded)    |
| `clusterSizes`      | clustering                       | number[] (per cluster, in label order)                             | `n_clusters`           |
| `projection`        | clustering                       | `{ x: number[], y: number[], cluster: number[] }`                  | 500 points (seeded)    |
| `silhouetteSamples` | clustering                       | `{ value: number[], cluster: number[] }`                           | 500 samples (seeded)   |
| `scoreHistogram`    | anomaly                          | `{ edges: number[], counts: number[], threshold }`                 | 50 bins                |
| `scorePoints`       | anomaly                          | `{ index: number[], score: number[], anomaly: boolean[] }`         | 500 points (seeded)    |
| `featureImportance` | classification, regression, semi | `{ feature: string[], importance: number[], method: string }`      | top 10                 |
| `mlpProgress`       | MLP classification, regression   | `{ epoch: number[], loss: number[] }`                              | `max_iter` entries     |
| `qValueHistogram`   | reinforcement_learning           | `{ edges: number[], counts: number[] }`                            | 50 bins                |
| `tdErrorHistogram`  | reinforcement_learning           | `{ edges: number[], counts: number[] }`                            | 50 bins                |
| `fqiProgress`       | reinforcement_learning           | `{ iterations: number[], meanQ: number[], tdErrorMean: number[] }` | `n_iterations` entries |
| `episodeReturns`    | reinforcement_learning           | `{ returns: number[] }`                                            | 500 (seeded)           |

Existing scalar metrics are unchanged and continue to populate the metrics list; S1, A2, C3 and the
job summary read them directly and need no new key. For reinforcement learning, RL1–RL3 depend on
`charts` keys above (and the evaluation Q/TD distribution collected by the worker).

### 4.2 Storage and API

- The `job_metrics.charts` JSONB column exists (migration `0002_add_charts_column.py`) alongside `metrics`.
- The `charts` field is present in the job poll payload (`GET /api/v1/jobs/{jobId}`). For reinforcement learning, the worker computes `qValueHistogram`, `tdErrorHistogram`, `fqiProgress`, and `episodeReturns` (when episode column declared) per §3.7. For MLP jobs it additionally computes `mlpProgress` (per-epoch loss) per §3.8.
- Payload is bounded with the caps above; sampling uses the job `randomSeed` and binning is server-side.
- A chart with no data (for example `perClass` absent, or `silhouette` omitted) is simply absent
  from `charts`; the frontend hides that card.

## 5. Rendering — visx

**Decision: visx 4.x** (`@visx/*`), rendered as SVG in React components under
`packages/frontend/src/components/charts/`. How-to: [`core/visx.md`](../../08-tech-stack/frontend/core/visx.md).

- **Why:** every series arrives pre-aggregated and capped ([§4](#4-data-contract-implemented)), so the
  work is scale/axis/shape maths rather than data wrangling. visx provides that maths as small,
  tree-shakeable React primitives, is TypeScript-first, and is React 19-ready. SVG keeps the DaisyUI
  token theming and the per-chart text fallback ([§6](#6-accessibility)) straightforward.
- **Packages:** import only what each chart uses — `@visx/scale`, `@visx/axis`, `@visx/shape`,
  `@visx/group`, `@visx/tooltip`, `@visx/responsive` (sizing); add `@visx/curve` only if a
  non-default line curve is used. Pin exact versions and record them in
  [`08-tech-stack.md`](../../08-tech-stack.md) §4.5 and `packages/frontend/package.json` together.
- **Components:** a thin local layer — `BarChart`, `GroupedBarChart`, `Histogram`, `ScatterChart`,
  `LineChart`, `Heatmap`, `Donut`, `SilhouettePlot`, `FeatureImportance`, `ChartWrapper` — each
  taking a typed discriminated-union prop and delegating scales, axes, and tooltips to visx. The
  heatmap (C1) composes `@visx/group` rectangles.
- Colours come from the semantic tokens and must keep AA contrast on `base-100` in both themes; never
  hard-code hex values.
- **Rejected:** **Recharts 3.x** — drags Redux Toolkit, react-redux, immer, and `victory-vendor` into
  a fixed, pre-aggregated set and still cannot draw the confusion-matrix heatmap. **react-chartjs-2**
  and **echarts-for-react** — Canvas renders no selectable text and ignores CSS token theming, which
  breaks the accessibility fallback and light/dark theming. **Hand-rolled SVG** — would reimplement
  scales, axes, and tooltips that visx already provides.

## 6. Accessibility

Per [`accessibility.md`](./accessibility.md):

- Each chart is `role="img"` with an `aria-label` stating the takeaway, plus a visible caption.
- Every chart is backed by a visually-hidden `<table>` (or an expandable "Show values" `<details>`)
  carrying the same numbers, so a screen reader user is not dependent on the graphic.
- Colour is never the only channel: classes/anomalies also use labels, ordering, or patterns.
- Axes, ticks, units, and the direction ("higher is better") are text, not colour alone.
- Tooltips and hover affordances are enhancements and keyboard-reachable if present.
- `prefers-reduced-motion: reduce` suppresses any entry animation.

## 7. Empty and degenerate states

| Situation                                      | Treatment                                                               |
| ---------------------------------------------- | ----------------------------------------------------------------------- |
| Job not `completed`                            | Model report section not rendered                                       |
| Job `failed`                                   | Section not rendered; the error alert is the report                     |
| `charts` null or a key absent                  | That card is hidden; the metrics list is unchanged                      |
| `silhouette` omitted (all rows identical)      | Hide K3; note "cluster separation is undefined for this data"           |
| Regression hold-out smaller than the point cap | Plot every point (no sampling) and state the count                      |
| Class count above the cap                      | Show the top classes by support and note the truncation                 |
| Estimator exposes no importance                | Hide M1                                                                 |
| RL episode column absent                       | Hide RL4; note "episode returns unavailable (no episode column mapped)" |
| FQI produced degenerate TD distribution        | Hide RL2 or show empty histogram with note                              |

## 8. Chart export (FEATURE-12)

Each rendered chart card exposes a download dropdown (visible on hover/focus) with two options:

| Format | Method                                      | Filename                 | Notes                                              |
| ------ | ------------------------------------------- | ------------------------ | -------------------------------------------------- |
| SVG    | `XMLSerializer` on the chart's root `<svg>` | `{jobId}-{chartKey}.svg` | Preserves current theme (CSS variables)            |
| PNG    | `html-to-image` → offscreen canvas @ 2× DPI | `{jobId}-{chartKey}.png` | Captures current theme as rendered; transparent bg |

The dropdown is a native `<details>`/`<summary>` (or headless UI `Menu`) for keyboard accessibility.
The button is icon-only, top-right of the card, shown on hover/focus.

**Metrics download:** a "Download metrics.json" button in the Downloads section saves the full
metrics object as `{jobId}-metrics.json` (pretty-printed JSON, `application/json`).

## 9. Out of scope (this iteration)

Elbow / metric-vs-cluster-count (requires refitting several models), 2-D PCA explained-variance
panels, partial-dependence and ICE plots, learning curves, multiclass ROC/PR, probability
calibration curves, confusion-matrix drill-down into individual rows, and cross-job comparison
charts on `/jobs`.

## 10. Open decisions

1. **Transport** — decided: bounded `charts` in the terminal poll payload (simplest, no extra
   fetch). A dedicated `GET /api/v1/jobs/{jobId}/report` endpoint is the fallback if the payload grows.
2. **P2 charts** — elbow/ROC/calibration curves etc. ship only if a concrete need appears.

Rendering is decided: visx 4.x ([§5](#5-rendering)).
